## 打开预览

构建后在 docs 目录运行：

```sh
python3 -m http.server 8766 --bind 127.0.0.1
```

浏览器打开 <http://127.0.0.1:8766>。也可直接打开 `index.html` 阅读；本机保存和下载以 HTTP 预览为准。

站点运行不需要 npm、服务器账户或在线服务。正式站：https://fe-guide.pages.dev/ 。提交 main 后由既有 Cloudflare Pages 集成发布 docs。旧版入口与回退方法见 [发布记录](RELEASE_AND_ROLLBACK.md)。

## 修改内容与重建

`source/火焰纹章万缕千丝_完全攻略手册.md` 是攻略正文，`source/_daily_log.json` 是继承的历史记录。`docs/data/chars.json` 维护图像和别名。修改后执行：

```sh
python3 -m pip install -r requirements.txt
python3 tools/build_site.py
python3 -m unittest discover -s tests -v
```

`source/negotiations.json`、`source/builds.json`、`source/story.json` 分别维护交涉明细、培养方案和三部流程；页面来源核对不等于游戏实测。新增条目须保留具体来源、适用路线和未确认条件。

生成 `docs/data.js` 与 `source/sources.json`。不要直接修改生成文件；界面和样式分别在 `web/app.js`、`web/styles.css`、`web/index.html`。

来源检查默认只列出待查地址：

```sh
python3 tools/check_sources.py --host gamewith.jp --limit 5
```

显式加上 `--check` 才会访问网络，并将结果写入 `research/latest-check.json`。403、429、robots 限制和访问失败均保留为受限状态。页面哈希变化只能提示需要复核，不能证明攻略机制发生变化。

## 本轮检查发现

1. 原站首页以篇章目录为中心，同一角色的招募与送礼分散在两篇长文中；新版按角色合并，保留原文入口。
2. 原生成器多次构建目录时会产生不一致的锚点。已观察到原首页链接带 `-1` 后缀，正文 ID 没有该后缀。新版使用固定章节 ID，并检验每个静态直达地址。
3. 原站首页日期硬编码为 2026-09-28，更新日志已到 09-29。新版明确展示日志快照日期，不宣称是逐条核验日期。
4. 原站 A/B/C 混用了站点身份和论断可信度。新版把来源类型、历史评级、当前核验状态分开；后续需要关联独立证据，而非只数转载站点。
5. 旧版更新说明里的 `checked` 同时包含来源数量和编辑描述。新版展示具体修订条目，不将该字段当作统计数字。
6. 原版大量彩色同款卡片、重复标签和长目录争夺注意力；新版将任务入口、阅读列表与轻量清单分开，用统一色彩和字号建立层级。
